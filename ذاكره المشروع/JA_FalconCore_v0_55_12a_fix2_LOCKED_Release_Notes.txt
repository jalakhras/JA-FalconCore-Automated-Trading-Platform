JA FalconCore v0.55.12a-fix2 — Broker Session Schedule Close Fix
Status: LOCKED / ACCEPTED
Date: 2026-05-16

Official decision
v0.55.12a-fix2 is accepted as the new official LOCK after successful behavioral validation across Regression OFF, Stop New Trades ON, Daily Close ON, Weekend Close ON, and All Safety ON.

Baseline
Previous official LOCK: v0.55.11f — Session Boundary User Override Inputs.
New official LOCK: v0.55.12a-fix2 — Broker Session Schedule Close Fix.

What changed
- Added final user-facing close safety controls with simple names:
  input bool StopNewTradesBeforeClose = false;
  input int  StopNewTradesBeforeCloseMinutes = 3;
  input bool CloseTradesBeforeDailyClose = false;
  input int  DailyCloseSafetyMinutes = 3;
  input bool CloseTradesBeforeWeekend = false;
  input int  WeekendCloseSafetyMinutes = 3;
- All boolean safety options default to false.
- All safety minute values default to 3.
- Close-time detection uses broker/server symbol session schedule through SymbolInfoSessionTrade.
- It does not depend on the user's PC clock, local Jordan time, or incomplete runtime bar history.
- CopyTime-based close-time inference from fix1 was removed from the session-boundary decision path.

Why fix2 was required
v0.55.12a-fix1 incorrectly inferred market close from currently available tester bars, causing false-positive blocks and closes at normal intraday times. fix2 resolves this by using broker session schedule data.

The new inputs are User Safety Overrides, not profit optimization defaults. All safety toggles remain OFF by default. Users can enable them manually if they prefer reduced close/weekend exposure even when it may reduce profit.
